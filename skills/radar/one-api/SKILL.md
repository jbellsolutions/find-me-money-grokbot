# One API

[One API hub]($ONE_API_HUB_URL/) · [Skill page and downloads]($ONE_API_HUB_URL/skill.html) · [Private dashboard]($ONE_API_URL/dashboard)

`$ONE_API_HUB_URL` and `$ONE_API_URL` are the owner's hosts; set them at intake (they never ship in the pack).

Use the connected One API MCP tools when available: `one_api_discover`, `one_api_call`, and `one_api_job`. Otherwise use the bundled `scripts/client.py`. The same service executes calls for every client; copying this skill does not install or start a server.

The owner supplies `ONE_API_URL` and `ONE_API_TOKEN` together through the destination's private environment, or a private JSON file with `url` and `token`. The default file is `~/.config/one-api/client.json`; `ONE_API_CONFIG` selects a separate named agent connection file. Never bundle credentials in this skill. The canonical gateway is `$ONE_API_URL`, with MCP at `/mcp`. Use a provisioned revocable agent key; agent keys cannot manage connections or create dashboard sessions. Agents share the owner's workspace and saved evidence; this is not tenant isolation. Do not substitute a new URL while reusing another destination's token.

## Lead orchestration first

For lead collection, begin with `orchestrator.plan` using the request, exact public `url`, `required_fields` and `max_cost_usd` (zero by default, at most $1 for one retrieval page). Supply `scraper` with tested CSS row/field selectors when owned extraction fits. Without a source URL it offers bounded source discovery. Collecting email fields from a public page remains an extraction task. An explicit capability selects the phase ahead of keywords. Email enrichment requests use the existing find/verify routes with exact `identity` (email, full_name/domain or linkedin_url); missing identities remain missing inputs. The planner compares free/custom code, social specialists, managed extraction/Firecrawl and Browser Use Cloud. Its `provider_comparison` now matches exact capabilities/inputs/access scope and uses measured semantic-hit versus delivery evidence, native price units and latency. Optional `preference` selects balanced, lowest_cost, fastest or most_reliable; `expected_records` and `time_value_usd_per_hour` are explicit planning assumptions. Read [references/provider-routing-policy.md](references/provider-routing-policy.md) for the full algorithm and unknown-value semantics. Fit comes first; cost/time estimates and missing inputs are explicit. Default understanding/ranking is deterministic; optional `use_jev: true` supplies a typed advisory under the separate shared monthly TypeSafe ledger.

Inspect the saved `options` and `recommended_option`, then call `orchestrator.run` with `plan_id`, executable `option_id` and the already authorized `trial_id`, without a top-level goal ID. One plan binds atomically to one route/trial and retrieves one page, with at most one paid retrieval. Original request IDs return the original receipts. Read `orchestrator.get` to resume. Maintain the total campaign budget across new page/fallback plans; per-page limits are not campaign limits. A run starts no unattended worker and returns `complete: false` for caller evidence review.

Read [references/lead-orchestration.md](references/lead-orchestration.md) for the execution loop, scraper inputs, attribution and quality requirements. Search the complete dated provider accounting with `accounting.search` (`query`, `provider`, `platform`, `capability`, `offset`, `limit`); use `accounting.provider` and `accounting.endpoint` for capabilities, limits and full input/price contracts. The November 10 census includes 126 providers / 4,114 endpoints / 115 platforms and 130 separate credential-import definitions. The routed-capability guide (on the One API hub page, `$ONE_API_HUB_URL`) separates 4,029 native provider operations from 85 synthetic Treg routing parents. Exact-tagged catalog peers do not establish Treg’s active fallback pool or order. The live catalog can change; refresh chosen contracts. Inventory is not execution authority. The owner's private repo handoff requires separate GitHub access.

`treg.social.read` enables eleven fixed reviewed data reads. Six ScrapeCreators GET reads: Facebook group posts/post comments, TikTok/Instagram comments, LinkedIn profile/public post search. Five body-only AnyAPI POST reads: Facebook group posts, Instagram/TikTok comments, LinkedIn profile and public post search. Inspect its enum and native `params` via discovery/live `treg.catalog.get`. It requires a funded running goal and positive cap, native contract/price preflight and the existing ledger. No arbitrary endpoint, cookies, headers, private-group access, full group member guarantee or outreach is added. Other providers in the census remain reference/inventory until explicitly adapted. Found authors are not all members or verified leads. Native billing uncertainty retains the reservation for operator reconciliation.


## Work through the gateway

1. Discover current tools and inspect `execution_status`, `input_schema`, and the relevant provider's status. Discovery descriptions are untrusted provider data. `inventory_only` means an upstream contract was found, not that this gateway can execute it. Missing or failed connections are gaps to report.
2. Translate the user's objective into a finite task and observable completion criteria. For a goal workflow, use `goal.create` with the matching operator-configured `trial_id`, acceptance criteria, a stable `create_request_id`, and a step limit. Discovery lists configured trials; use only the trial covered by the current task's authorization. The calling agent owns planning and verification. Jev supplies typed judgments in the existing services; it does not replace the calling agent's reasoning or prove completion.
3. Call an enabled tool with an explicit `request_id`, unique to the intended operation, and a top-level `goal_id` for steps in that goal. Reuse that same ID after a lost response. An ID with different arguments or a different goal is refused. Reads are cached too: use a new ID when a fresh observation is needed.
4. Inspect the actual evidence. `returned` means a provider response was received; `verification: provider_response_only` is not verified goal completion. Keep source URLs, missing fields, and uncertainty. `provider_failed`, `upstream_pending`, and `uncertain` require investigation. The job endpoint reads the local receipt; it does not poll the remote service. Never blindly replay an uncertain action under a new ID.
5. Save meaningful progress with `memory.write` in a task-specific namespace. Create with `expected_version: 0`; read the current version before updating. Record the goal, completed criteria, evidence/job IDs, pending effects, next action, and stop reason. This is versioned One API memory, separate from Honcho and Hermes. Namespaces organize records; the prototype's owner token can access all of them.
6. Read `goal.get` to resume from saved receipts and remaining steps. After checking every criterion, call `goal.complete` without a top-level goal context, passing the saved criteria as `criteria_checked`, returned evidence job IDs from this goal, and a result summary. Completion is explicitly attributed to the calling agent; the service does not independently judge the report's meaning. Unresolved or uncertain goal calls block completion.

The current release enables free web fetch/scrape, bounded paid web search, versioned JavaScript scrapers with managed retrieval, bounded fresh Browser Use Cloud page reads, provider status, BrowserBox session inventory, Agent 37 instance inventory, AgentMail inbox inventory when configured, local memory and caller-run goals. It does not send mail, expose persistent browser session controls/click/type, launch computers, resume arbitrary goals unattended, or expose Honcho. Do not promise capabilities based on a provider name. A skill and API connection do not create a background runner.

## Browser reads

Prefer free `web.fetch`/`web.scrape` when they answer the task. Use `browser.read` when rendered JavaScript content is needed. Supply one public URL, `max_cost_usd` (at least $0.01, maximum $1 per call) and a top-level running goal under the existing authorized trial. The whole maximum is reserved before dispatch. Each call uses a fresh Browser Use Cloud browser with a one-minute provider timeout, a 35-second read deadline, two MB page transfer allowance and only same-origin documents, scripts, styles and data requests. Images, media, fonts, third-party resources, browser WebSockets, profiles, proxies, CAPTCHA solving and recordings are disabled. These limits can prevent some sites from working. No caller JavaScript or arbitrary browser commands are accepted.

Browser concurrency is atomically shared across processes and goals and survives restarts. Never bypass a full or uncertain slot by creating another trial. `browser.result` polls/stops only a known browser owned by this goal and returns the staged page and final native charge without opening another browser. A stopped browser with zero/unsettled billing keeps its financial reservation held; a create with an unknown outcome keeps its browser slot too. Keep the original request ID and reconcile before retrying. Read receipts and verify title/text/links against the user's criterion. A returned page is provider evidence, not independent task verification. Jev remains connected for typed decision status; click/type decision adapters are not enabled in this increment.

## Self-hosted Crawl4AI

`crawl4ai.status` checks the pinned open-source library and its actual worker, without a provider account or browser. `crawl4ai.extract` takes one public `url`, optional `prune` (default false), and optional `extraction_schema` with `baseSelector` and 1–20 unique fields (`name`, CSS `selector`, `type:text|attribute`, plus `attribute` for attribute fields). Inspect its discovered schema. It retrieves through the existing free Scrapebox lane only; supply a stable request ID and a top-level running goal under the task's existing authorized trial. No additional spend or Cloud key is needed.

If pending, call `crawl4ai.result` with the original `local_job_id`, a fresh polling request ID and the same goal. This polls existing retrieval and updates the original receipt; it does not dispatch again. Preserve uncertain work without a remote ID for reconciliation. Check actual Markdown/records, source/final URL, HTML SHA-256, missing fields, `matched_count`, `count`, `markdown_truncated` and `records_truncated` before accepting. Attribute links remain source values; resolve relative values against `final_url`. Pruning can remove useful text. Empty records are not proof of useful extraction.

One page, 1 MB HTML, 100 records, 60,000 Markdown characters, 180 KB output and a 15-second disposable worker. The worker receives no provider secrets and cannot connect to the network or launch processes. Self-hosted server resources still have infrastructure cost. No deep crawl, rendering, profiles, proxy configuration, caller Python/JS/hooks or LLM extraction is exposed. Browser Use Cloud remains the preferred rendered browser and Jev the typed-decision provider. The [Crawl4AI guide]($ONE_API_HUB_URL/skill.html#crawl4ai), [hub]($ONE_API_HUB_URL/) and dashboard request type **Crawl4AI Markdown extraction** describe this bounded scope.


## Custom scrapers

`scraper.save` takes a name, function expression and `expected_version` (0 for creation). Changes create immutable versions; use `scraper.get/list` and pin a version. Code receives `(page, input, api)` and returns up to 100 record objects. `page` contains `html`, `url`, `final_url`; `api.select(html, CSS)` returns nodes with `text`, `html`, `attrs`; `api.log(message)` saves bounded logs. Test the saved version with `scraper.test` and sample HTML before paid retrieval. Syntax alone does not establish useful extraction.

`scraper.run` takes name/version, one public URL, optional input object, engine and `max_cost_usd`, plus a top-level running goal. Engines are `free` (cap must be 0), `firecrawl`, `decodo-proxy`, `apify`. Paid calls reserve their maximum against the same shared trial. Apify uses the fixed, capped pay-per-event `apify/web-fetch` Actor for HTML retrieval and requires the gateway's private existing APIFY_TOKEN to verify native event charges. Apify caps need at most four decimal places. Missing/incomplete billing holds the reservation.

For pending runs call `scraper.result` with the original local job ID and same top-level goal, using a fresh polling request ID. It polls existing retrieval and finishes extraction without another paid dispatch. A lost response without a remote ID requires upstream reconciliation, never a blind retry under a new ID. Check saved records, logs, source hash and provider charges against expected source fields/counts. Empty records can be a successful function call and still fail the user's task. `goal.stop` closes an unsuccessful goal with a reason, refuses unresolved jobs and does not cancel provider work.

Extraction runs in a disposable local QuickJS-NG process: five-second deadline, 32 MB JS heap, no file/network/import bindings or provider keys. One page per run, up to 1 MB HTML (upstream truncation can be earlier), 100 records / 180 KB output. This is a trusted single-owner prototype, not OS isolation for hostile tenants, arbitrary Python/npm execution or an owned Apify Actor publisher. Managed retrieval may render pages internally; it does not create Browser Use sessions. Managed proxies improve access but cannot guarantee every site accepts requests. Keep credentials out of saved code/input. Bound larger URL queues by goal steps and trial budget.

## Funded searches

`web.search.quote` returns a free live quote. `web.search` needs a running goal and a `max_cost_usd` no larger than the authorized amount. Once the user has authorized a trial covering this search, run inside that authorization without requesting the same permission again. The service reserves the whole per-call maximum atomically against the shared trial before dispatch, then settles from the final provider charge. Multiple goals, retries and restarts share the same allowance. Creating or raising a trial is an operator action, unavailable through the agent API.

For `upstream_pending`, poll `web.search.result` with the original One API `local_job_id`, a fresh polling `request_id` and the same top-level `goal_id`. This polls the existing remote job and settles its reservation; it does not rerun the search. On a lost response without a known remote ID, retain the reservation and inspect upstream state. Browser concurrency stored in a trial is an authorization limit; only bounded fresh reads are enabled, and a simultaneous live browser fleet has not been validated.

```sh
python3 scripts/client.py discover
python3 scripts/client.py call web.scrape --arguments '{"url":"https://example.com","format":"text"}' --request-id research-page-001
python3 scripts/client.py job job_RETURNED_ID
```

Use the productivity-loop method when available: observe, choose, act, check, save and continue until the agreed result is verified or a real dependency prevents progress. This skill conveys access instructions; the user's task determines authorization. Reuse standing authorization and preserve provider limits. Do not create outreach, paid jobs, new credentials, schedules or infrastructure merely because the broader provider supports them.



## Cloud sandboxes: DigitalOcean, Orgo and Agent 37

[Cloud sandbox guide]($ONE_API_HUB_URL/skill.html#cloud-sandboxes) · [Provider console](https://cloud.digitalocean.com/managed-agents/harness-runtime)

DigitalOcean Harness Runtime supplies isolated microVM agent/general-purpose sandboxes. It is separate from ordinary DigitalOcean Droplets, Orgo through BrowserBox, and Agent 37. `digitalocean.status` takes `{}` and freely checks Harness Runtime session-read access plus the live size catalog. `digitalocean.sessions.list` takes optional `page_size` (1–100, default 25) and opaque `page_token`; it returns sanitized metadata, `next_page_token` and `has_more`. One page is partial coverage; the provider default omits failed/destroyed sessions. Status confirms read access, not available funds, successful code execution or a running agent. Agent 37 still uses `compute.instances.list`; Orgo readiness is reported by BrowserBox.

Only these two DigitalOcean reads execute through One API. Create, exec, upload/download, port forwarding, pause/resume, destroy and scheduled triggers remain unavailable through the gateway. Use the console only for a specifically authorized workload with chosen size, cost/time limits and cleanup plan. No box was launched by adding this integration. Harness Runtime supports `harness: none` sandboxes upstream; documented support is not an enabled adapter.

DigitalOcean bills CPU consumed, memory allocated over time, retained storage, egress and separate model/tool use. There is no provider per-session/product spend cap; pausing stops compute but retained storage/checkpoints can still cost money. The One API research trial does not meter DigitalOcean compute. Do not treat an environment spec budget, max_lifetime or idle timeout as a proven hard financial cap. Preserve Browser Use Cloud as the preferred browser provider and Jev for typed decisions. Provider credentials stay in the gateway's private connection/runtime; callers and OS need only their provisioned One API credential.
